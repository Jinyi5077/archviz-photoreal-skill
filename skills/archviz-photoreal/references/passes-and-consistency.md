# 通道识别与跨视角对应

## 文件配对与实际读取

主图是拍摄构图和可见几何的基准；通道用于交叉核对，不是新的设计参考。读取主图、同机位 Albedo 和 Normal；其他可用通道逐一判断用途。文件尺寸一致只能说明可能对齐，还需对照至少主体轮廓、支承/开口、岸线等位置，确认是同一次相机输出。主图裁切、通道未裁切时，先标记不对齐，不能直接作为控制输入。

配对示例：`场景 2.png` ↔ `场景 2_AI_Albedo.png` / `场景 2_AI_Normal.png` / `场景 2_AI_Material.png`。`图片.png` 也是合法主图。缺失通道不会让原图失效；记录缺失，利用其余证据。未知后缀不应默认为主图。

`inventory_render_set.py INPUT --out OUTPUT.json` 用 Python 3 标准库清点同层图像，读取 PNG/JPEG 尺寸并计算 SHA256。其他支持的图片扩展名仍配对，但尺寸无法解析时需通过图像工具确认。清单的 `visual_inspection` 字段始终待人工/模型视觉读取，不可当识别报告。

## 通道角色与误用

| 输入 | 可用信息 | 不允许的推断 |
| --- | --- | --- |
| 主图/Beauty | 当前相机、遮挡、明暗、原始材质观感及环境 | 阴影不是孔洞；模糊低细节不是允许重画几何 |
| AI_Albedo | 去除大部分光照后的颜色分区与边界线索 | 相同颜色不是同一对象；黑色背景不一定是实体 |
| AI_Normal | 可见表面朝向变化、折线和几何边界线索 | 不把彩虹色当材质；不是深度图、物体 ID 或可直接贴到表面的纹理；不未经确认断言坐标空间 |
| AI_Material | D5 专用 AI 后期输入之一，可辅助比较区域响应 | **不是 D5 单独导出的 MaterialID**；官方页面未给出完整编码，不能猜 RGB 含义、物体类别或稳定实例 ID；暗红/黑不表示损坏或应改成该颜色 |
| MaterialID | 已确认导出方式下的材质分组/选区参考 | 一个材质可跨多个物体；跨导出颜色未必稳定，不能充当全局建筑身份证 |
| ZDepth | 前后关系、景深线索，需确认编码和范围 | 不直接当距离米数；不恢复不可见背面 |
| AO | 接触关系和细缝线索 | 不把 AO 脏影烘焙进基础色，不能覆盖实际光照 |
| SkyMask / Transparent | 经核对的天空/透明表面范围 | 非天空不被天空替换，实体栏板不被转透明；遮罩方向需先核对 |
| Reflection | 镜面贡献的辅助观察 | 不把反射图当表面原色或复制到另一机位 |

通道颜色像素的统计不能替代语义识别。尺寸、文件头、哈希检查也不能确认内容身份。

## 几何约束记录

为每张图建立简明记录，至少包含：

- `camera`: 视角、画幅、原裁切和可见天空；未知的相机参数不编造。
- `locked_geometry`: 主体轮廓、支承、构件、分岔/孔洞、桥头/入口等落点。
- `surface_regions`: 水、岸墙、陆地、铺装、植被、主体、背景的范围与相邻关系。
- `contacts`: 物体接触哪个表面，是否浸水，哪些区域必须保持干燥；事实来源。
- `uncertainties`: 看不清的边界，是否需要用户/源模型证据；不能把不确定项写成确定标签。

归一化框 `[x0,y0,x1,y1]` 使用左上为原点、坐标 0–1，记录近似可见位置；不能把框冒充像素精确遮罩。主体区域重叠时记录遮挡次序。

例：用户明确“右前方桥墩在河岸上”。应记录 `contact=dry_bank`、证据为用户说明；提示词写明墩脚接触岸上铺装，保留其周围陆地和岸线，水只出现在确认水域。即使此前 AI 成图把它变成水中墩，也不能据那张成图延续错误。这个规则是场地接触关系的判断方法，不表示所有桥墩都在岸上。

## 跨机位物体对应

先读完整套输入，利用总平面/俯瞰建立相对方位，再核对平视和近景。可用证据：同一河弯、交叉口、建筑轮廓与屋顶、邻接关系、相机方向，以及在用户授权范围内只读取得的源模型对象 ID/世界坐标。屏幕“左边”“右边”只对当前视角有效。

为物理对象分配稳定 ID，例如 `BRIDGE_01`、`BUILDING_001`；为材质分配独立 ID，例如 `MAT_CONCRETE_01`。一栋建筑可有多个材质，一种材质可被多栋建筑使用。场景级 Normal 的颜色随机位/编码可能变化，不用于跨视角 ID 匹配。若只有图像，明确是视觉对应，不宣称恢复了模型实体 ID。

台账可用 JSON、CSV 或 Markdown，必须能表达：

| 字段 | 用途 |
| --- | --- |
| object_id / source_object_id | 稳定视觉 ID；可选源模型 ID，说明来源 |
| landmarks / match_confidence | 与道路、河岸、邻近建筑的关系；高/中/低置信度及依据 |
| observations | 哪些图可见、可见立面、归一化框或位置描述 |
| material_id / surface | 材质分配到具体表面，不对整图统一覆盖 |
| base_color / finish / opacity | 材质底色、表面质感、透明/实体性质 |
| layout / scale / orientation | 已有窗格、分缝、层高节奏；纹理物理尺度和对象坐标中的方向 |
| texture_reference / provenance | 用户参考或选定样本；保留现状、建议材质或用户允许的概念立面 |

锁定的是物体固有属性，不是每张图的 RGB 值。相同玻璃反射不同景物合理；相同窗格在另一个视角变成另一种布局不合理。没有比例依据时不编毫米数，用与门、层高或栏杆高度的相对尺度描述，保持跨图一致。

只向图像模型提供相关的可见对象信息：将台账 ID 转写成“右侧河岸靠近高架桥的四层长条楼”等可核对描述，并附相应参考。已生成图只可作为通过检查部分的外观参考；凡与源图冲突的形体，以当前原始主图为准。

## 通过标准

对照原图检查主体轮廓和构件位置、透视和裁切、陆水边界、支承落点、遮挡/开口及透明性。对照台账检查同一栋建筑的立面系统、底色、材质尺度和纹理方向。光照可改变明暗，不能改变这些身份特征。

若有真正的分割/边缘工具，可量化对应轮廓；不要用整图像素差分衡量材质编辑正确性，也不要用图像宽高相等声称几何已锁定。需要精确验收却没有相应证据时，标记“仅视觉复核，未做像素级几何验证”。
